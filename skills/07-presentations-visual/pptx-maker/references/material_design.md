# Material Design for Slides

這份 reference 只在使用者明示指定 Google Material 風格，或品牌規範已確認採用 Material 語言時才讀取。它是可選視覺語言，不是 `pptx-maker` 的預設答案。

## Purpose and fit

- 適合卡片式資訊、產品介紹、功能總覽、系統流程與需要明確層級的技術簡報。
- Material 的核心不是「做得像 App」，而是用表面、層級與有意義的動線讓資訊關係更清楚。
- 若任務只是靜態單頁大標宣言，或不需要卡片層級與表面關係，不必勉強套用。

## Execution rules

### Surface and elevation
- 把內容想成有層級的表面，而不是任意漂浮的模組。
- 可使用輕量陰影與 elevation 暗示層級，但必須節制；陰影是結構語言，不是裝飾。
- 不要讓每個元件都升高一層，否則層級失效。

### Card logic
- 卡片適合承載單一主題或資訊單元，尤其是不同資料型態或可變長內容。
- 使用卡片時，主內容要先被看到，輔助資訊與操作放在一致位置。
- 不要把本來適合快速掃讀的同質清單硬拆成一堆卡片，否則會降低掃讀效率。

### Grid, spacing, and shape
- 使用一致間距與 keyline；卡片集合需要穩定 gutter 與 margin。
- 圓角、卡片邊界與內距要一致，不要每頁都改規則。
- 內容應服從表面結構與可讀性，而不是為了模仿 UI 元件而堆疊元件。

### Typography and color
- 內容優先，字體與色彩應協助辨識主次。
- 可用明確品牌色，但不應掩蓋層級與可讀性。
- 若背景含圖片，確保文字仍保持足夠對比。

## QA checklist

- 是否用表面、層級與卡片關係傳達結構，而不是只做出「Google 感」。
- 卡片是否真的適合這頁內容，而不是把所有頁面都卡片化。
- 陰影、圓角、間距與卡片內結構是否一致。
- 主內容是否先被看到，輔助資訊與操作是否放在穩定位置。
- 是否避免把需要快速比較的同質內容拆成干擾掃讀的卡片堆。

## Common failure modes

- Symptom: 頁面看起來像一堆 App 截圖拼貼，資訊結構反而更亂。
  - Cause: 把 Material 誤解成元件堆疊，而不是表面與層級語言。
  - Fix: 回到 build spec，只保留真正有必要的卡片與分層，刪除裝飾性 UI 模仿。

- Symptom: 每張卡片都很像，但沒有主次，觀眾無法快速掌握重點。
  - Cause: 忘了用 hierarchy 強化最重要內容，只剩下表面容器。
  - Fix: 強化主卡、主標、主數字與主要行動區，讓 hierarchy 先成立。
