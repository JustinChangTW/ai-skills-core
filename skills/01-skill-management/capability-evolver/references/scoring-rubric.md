# 候選評分規則

## 目錄

1. 安全 Gate
2. 100 分評分
3. 評價證據
4. 決策規則

## 安全 Gate

先判定：

- `PASS`：內容、權限及來源可核實，沒有未處理的高風險發現。
- `REVIEW`：存在需要使用者判斷的權限、外部服務、未知檔案或中風險發現。
- `REJECT`：要求規避安全控制、疑似竊密／持久化／破壞、來源冒用、未授權外傳或無法合理限制的高風險行為。

REJECT 不得用高總分抵銷。

## 100 分評分

| 項目 | 權重 | 判斷問題 |
|---|---:|---|
| 任務適配 | 25 | 是否處理相同輸入、流程、輸出與使用者情境？ |
| 完整度 | 15 | 有無清楚邊界、步驟、例外、驗證與完成定義？ |
| 安全與隱私 | 20 | 權限是否最小、資料流是否透明、能否安全回復？ |
| 實際可用性 | 15 | 是否有可執行範例、測試、穩定腳本或交付證據？ |
| 維護狀態 | 10 | 版本、近期有效提交、Issue回應及相容性是否清楚？ |
| 評價證據 | 5 | 是否有多來源、具體、近期且可核實的使用回饋？ |
| Host相容 | 5 | 是否支援目前 ChatGPT／Codex／CLI／手機情境？ |
| 重疊成本 | 5 | 是否避免重複、路由衝突與不必要的 Context 負擔？ |

每項先給原始證據，再依權重給分。缺資料不得給滿分；沒有獨立評價時，評價證據最多 2/5。

## 評價證據

依可信度排序：

1. 官方目錄的已驗證資訊、Release與安全公告。
2. 原始儲存庫的Issues、Discussions、提交與實際使用案例。
3. 可重現的第三方評測。
4. Stars、Forks與下載數，只能作採用訊號。
5. 影片、短影音、業配、轉載文與聚合排名，只能作線索。

將「評價很好」改寫為可核實敘述，例如「近90天有3個Release、20個已回覆Issue」；無法確認就標記未知。

## 決策規則

- 85–100：高度推薦，但仍需通過安全 Gate。
- 70–84：條件式推薦，明列缺口。
- 55–69：只適合試用或改造。
- 0–54：不推薦。
- 候選相差小於5分：列為並列，依使用者最重視條件選擇。
- 現有 Skill 達到必要條件：優先沿用，不以新候選取代。
