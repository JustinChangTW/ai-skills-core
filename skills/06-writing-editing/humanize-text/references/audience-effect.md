# 受眾、效果與觀點盤點

AI 文字常見問題不只是句子生硬，而是「消失的受眾」與「消失的觀點」。前者讓文字像在自言自語，後者讓文字成為平均化整理，讀者看完不知道作者到底要推進什麼判斷。

這份文件用來在 rewrite 前決定內容編排。它不是內容策略大全，也不是要求每篇文字都變成強烈立場文；它只要求改寫時先知道誰要讀、讀完要做什麼，以及作者原文中有沒有可負責的觀點。

一旦完成受眾與觀點盤點，接著要讀 `coherence-argument-flow.md`，確認主張鏈、概念命名、段落顆粒度與階層關係一致。受眾決定「為誰編排」，觀點決定「推進什麼」，coherence 則確保文字不是局部順暢但整體斷裂。

## Audience-effect mapping

先回答四個問題，再改寫：

1. 主要受眾是誰。例：主管、同事、客戶、工程師、新手讀者、既有社群、反對方、決策者。
2. 讀者此刻帶著什麼問題。例：我該不該採用、我哪裡搞錯、這跟我有什麼關係、下一步要做什麼。
3. 預期效果是什麼。例：交換論點、釐清知識點、說服、通知、邀請回應、建立信任、輔助決策、促成行動。
4. 讀者最省力的閱讀路徑是什麼。例：先結論、先背景、先差異、先證據、先風險、先步驟、先開放問題。

缺少明確受眾時，先從媒介與內容推斷。Email 通常有收件人與下一步；技術文件通常有任務與前置知識；社群貼文通常有共鳴點與回應入口；內部提案通常有決策者、執行者與受影響者。

## 預期效果與編排策略

改寫策略必須由受眾與最終目的反推，不能先套用「順稿」再補一句受眾假設。若讀者最需要的是判斷、決策、行動或交換立場，文章開頭應優先回答讀者此刻在意的問題；原文若從背景、定義或平均摘要起手，通常需要重寫開頭，而不是只把句子修得順一點。

策略選擇時先判斷改寫幅度：

1. 只需改善語氣與句型時，用 `light polish` 或 `natural rewrite`。
2. 原文像提綱、清單或資料平均攤開時，用 `paragraph reconstruction`。
3. 原文開頭不服務受眾、核心主張太晚出現、段落順序削弱目的，或需要先建立讀者痛點 / 決策問題時，用 `structural rewrite`。

`structural rewrite` 可以重寫前一到兩段、提前作者觀點、調整段落順序或合併重複論點。它不是為了讓文字看起來變化更大，而是為了最大化受眾理解、判斷、回應或行動的機率。

### 交換論點與看法

先放作者觀點或疑問，再放理由與限制，最後留下可回應的空間。不要把所有觀點磨成中立摘要。讀者需要知道「你站在哪裡」與「你希望他回應哪一點」。

### 釐清知識點

先說讀者容易混淆的差異，再補定義與例子。不要先下百科式定義。若讀者是新手，用熟悉場景切入；若讀者是專業者，直接指出邊界與例外。

### 說服或推動採用

先對準讀者關心的成本、風險、收益與替代方案，再放主張。不要只堆優點。說服不是誇大，而是讓讀者能判斷為什麼此時此地值得做。

### 通知或同步

先放結論、變更、影響範圍與需要讀者做的事。背景放後面。通知型文字最忌把讀者逼著在長段落裡找重點。

### 建立信任

先承認限制、風險或不確定性，再說已知事實與下一步。不要用空泛保證取代清楚邊界。

### 輔助決策

先呈現決策問題、選項、取捨與推薦。事實資料要服務判斷，不要平均攤開。

### 促成行動

先說讀者要做什麼、何時做、做到什麼程度。理由與背景只保留足以支持行動的量。

## 觀點盤點

觀點不是憑空加戲，也不是把語氣變激烈。觀點是作者對材料的判斷、排序、疑問、限制或取捨。

### 可以強化的觀點

1. 原文已明示的主張。
2. 原文多次暗示的偏好或擔憂。
3. 原文已有事實能支持的判斷。
4. 作者對讀者的建議、疑問或提醒。
5. 對替代方案、限制、優先順序的取捨。

### 不可新增的觀點

1. 原文沒有支持的價值判斷。
2. 假裝作者親身經歷、試用、訪談或研究過。
3. 虛構的反對者、受眾反應、數據或案例。
4. 把純事實摘要硬改成評論。
5. 把學術、法務、醫療、財務等正式內容改成個人立場文。

## 觀點補強方式

弱觀點通常長這樣：文字平均、每段都像摘要、所有選項都「各有優缺點」、結尾只說「值得關注」。修法不是提高音量，而是做取捨。

可以用這些方式補強：

1. 把隱含判斷改成明句，例如「真正麻煩的不是工具，而是導入後誰負責維護」。
2. 把平均陳述改成排序，例如「短期先處理資料品質，比先換工具更實際」。
3. 把模糊好處改成讀者利益，例如「這能讓客服少查三個系統，而不是只說提升效率」。
4. 把空泛結尾改成下一個討論點，例如「如果要推，下一步應先確認權限與資料同步成本」。
5. 把過度中立改成可討論主張，例如「我不反對導入，但反對在流程還沒定義前先買工具」。

## 受眾缺席檢查

改寫後逐項檢查：

1. 讀者能在前幾句知道這段跟自己有什麼關係嗎？
2. 讀者知道作者希望他理解、回應、判斷或行動的是什麼嗎？
3. 編排是否符合讀者最省力的路徑，而不是作者把資料平均攤開？
4. 觀點是否有原文事實支撐？
5. 是否因為追求自然，而新增了原文沒有的立場或經驗？

## 與 voice profile 的關係

`voice-profiles.md` 決定說話方式，這份文件決定說給誰聽、為了什麼效果、先說什麼。兩者都需要，但不能互相取代。語氣再自然，如果沒有受眾與效果，仍然會像自言自語；觀點再清楚，如果語氣不適合受眾，也會降低效果。
