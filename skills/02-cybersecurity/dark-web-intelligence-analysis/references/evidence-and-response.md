# 證據分級與應變

## 證據等級

| 等級 | 條件 | 可採取行動 |
|---|---|---|
| A 已確認 | 內部日誌／端點證據與可信外部情報吻合，或組織正式確認 | 啟動事件應變、保存證據、依法規與程序通報 |
| B 多源一致 | 至少兩個獨立可信來源，且識別資訊、時間與對象吻合 | 提高監控、要求資產／帳號責任人立即查證 |
| C 單一可信來源 | 一個可追溯來源有具體技術資料，但尚無內部命中 | 列為調查線索，不做不可逆處置 |
| D 未驗證聲稱 | 論壇、勒索公告、社群貼文或聚合站，缺乏可驗證證據 | 監測與交叉查證，不對外定性 |
| E 無法判定 | 來源、時間、識別資訊或資料完整性不足 | 記錄缺口，不下結論 |

## 常見誤判

- 舊外洩帳號已停用或密碼已更換。
- 同名公司、相似網域、轉寄地址或第三方帳號被錯誤歸屬。
- 共享IP、CDN、VPN、NAT或雲端主機造成錯誤關聯。
- Sinkhole DNS紀錄只指向遞迴DNS伺服器，不一定是感染終端。
- IOC已被回收、清理或轉為研究用途。
- 勒索團體重複刊登、虛報或把供應商事件說成客戶事件。
- Infostealer紀錄可能來自個人設備，未必代表公司端點遭入侵，但仍可能危及公司帳號。

## 應變對照

| 發現 | 先做 | 證實後 |
|---|---|---|
| 員工帳密／Infostealer | 確認帳號與時間、檢查登入與裝置、聯絡帳號責任人 | 重設密碼、撤銷Session與Token、重綁MFA、隔離及鑑識端點 |
| 惡意IOC命中 | 檢查時間、方向、程序、DNS與EDR脈絡 | 隔離主機、封鎖經驗證IOC、搜尋同類活動、保存證據 |
| 勒索或資料外洩聲稱 | 保存公開頁面中繼資料、通知事件窗口、比對內部異常 | 啟動IR、法遵／個資／主管機關評估及對外溝通程序 |
| 已遭利用漏洞 | 比對產品、版本、曝露面及緩解狀態 | 緊急修補／緩解、Threat Hunting、驗證修補與持續監控 |
| 仿冒網站 | 保存安全截圖、DNS／憑證與品牌證據 | 通知品牌／法務／防詐窗口、申請下架、警示客戶、監測變種 |
| 供應商外洩 | 確認服務、資料及連線依賴 | 啟動第三方事件程序、限制連線／憑證、評估通知與持續營運 |

高影響動作（帳號停用、封鎖、對外通報或公開歸因）必須基於相稱證據與既定授權，不由Skill自動執行。
