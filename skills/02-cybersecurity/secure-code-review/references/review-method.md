# 審查方法

## 快速 PR

1. 取得基準與變更差異，不把既有未變更問題混成此次 PR 缺失。
2. 依風險排序：認證／授權、交易與金流、密碼學、外部輸入、檔案處理、外部呼叫、密鑰、部署與依賴。
3. 以 `git blame`／歷史理解被移除控制的目的，檢查安全回歸。
4. 搜尋變更函式的呼叫者、公開入口及下游影響，估計 blast radius。
5. 檢查新增或修改路徑是否有正向、負向、邊界與權限測試。

## 完整靜態審查

1. 建立入口、信任邊界、身分、權限、資料資產與 sink 地圖。
2. 從高價值資產向外回溯，再由外部輸入向內追蹤，交叉比對。
3. 特別檢查失敗路徑、預設值、初始化、重試、逾時、競態、解析器差異及跨元件假設。
4. 每個候選發現記錄 `entrypoint → propagation → control → sink → impact`。

## 工具結果覆核

1. 保留工具名稱、規則 ID、版本及掃描基準。
2. 重新讀取真實程式路徑，不照抄掃描器說明。
3. 合併相同根因、區分已確認、待確認、誤報及強化事項。
4. SARIF 嚴重度只是輸入；最終分級以可達性、攻擊條件及影響為準。

## 候選漏洞驗證問題

- 攻擊者是誰，需具備什麼權限與位置？
- 外部輸入能否抵達所稱 sink？每一步是否有型別轉換、正規化或驗證？
- 是否有 middleware、框架預設、資料庫約束、網路隔離或其他控制阻止攻擊？
- 可造成什麼具體影響？只是錯誤訊息、資訊片段或 DoS 推測，不得誇大。
- 問題是否只存在於測試、範例、不可達分支或非正式設定？
- 修補是否真正切斷攻擊路徑，是否破壞合法功能？

## 常見審查領域

- Injection：SQL、OS command、模板、LDAP、NoSQL、Header、Log。
- AuthN/AuthZ：登入、MFA、Session、Token、IDOR/BOLA、角色與物件所有權。
- 資料：個資、密碼、金鑰、日誌、錯誤訊息、備份及測試資料。
- 邊界：SSRF、檔案上傳、路徑穿越、XXE、反序列化、Webhook、Redirect。
- 邏輯：競態、重放、順序繞過、額度／價格／狀態、冪等性。
- 供應鏈：鎖定檔、來源、typosquatting、maintainer 變更、建置腳本與 CI 權限。
- AI／LLM：Prompt injection、工具授權、資料外洩、輸出信任、RAG 污染及代理越權。

清單用來找方向，不作為漏洞成立證明。
