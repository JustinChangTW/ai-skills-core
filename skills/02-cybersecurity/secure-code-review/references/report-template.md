# 報告格式

## 發現摘要欄位

| 欄位 | 要求 |
|---|---|
| ID | 穩定編號，例如 SCR-001 |
| 標題 | 根因＋影響，不用聳動語言 |
| 嚴重度 | Critical／High／Medium／Low／Info |
| 信心 | High／Medium／Low，與嚴重度分開 |
| 狀態 | 已確認／需人工確認／強化建議／排除 |
| 位置 | 檔案、函式、路由及可靠行號 |
| CWE／OWASP | 能精確對應才填 |

## 發現詳情順序

1. 事實與根因。
2. 證據鏈：入口、傳遞、控制、sink。
3. 攻擊者能力與必要條件。
4. 可造成的具體影響及受影響資產。
5. 既有緩解與剩餘風險。
6. 建議修補、替代方案及副作用。
7. 驗收與回歸測試。
8. 外部查證來源與查詢日期。

## 分級原則

- Critical：低阻力即可造成核心系統全面失陷、重大資產損失或大規模敏感資料外洩。
- High：可造成重大未授權操作、敏感資料外洩或高權限取得，且攻擊路徑可信。
- Medium：影響明確但需較高前置條件、範圍有限或有部分緩解。
- Low：可驗證的小範圍弱點或防禦深度不足。
- Info：正向控制或不構成漏洞的改善機會。

嚴重度依「可利用性 × 影響」判定；若只有樣式訊號或缺少完整資料流，狀態應為需人工確認或強化建議。

## 安全用語

- 使用：「本次審查範圍內未發現已確認漏洞。」
- 避免：「程式完全安全」「沒有任何漏洞」「已符合所有法規」。
- 密鑰只報類型與位置；範例使用虛構、無效值，不複製真實秘密。
