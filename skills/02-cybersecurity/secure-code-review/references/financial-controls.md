# 金融業強化檢查

此檔只提供技術審查視角，不自行宣稱臺灣法規合規。法規、主管機關要求與業別差異交由 `taiwan-isms-audit-expert` 查證。

## 共通高風險路徑

- 交易建立、授權、覆核、放行、撤銷、退款及沖正是否維持狀態完整性。
- Maker–Checker、職務分工與高權限功能是否能被平行 API 或批次路徑繞過。
- 金額、幣別、帳號、受款人、費率及交易狀態是否在可信端重新驗證。
- 防重放、冪等鍵、序號、時效、競態鎖定與重複扣帳處理。
- 客戶身分、帳戶與交易物件是否逐筆做伺服器端授權，避免 BOLA／IDOR。
- MFA、裝置綁定、Session、Token 撤銷與風險升級驗證是否涵蓋敏感操作。
- 稽核軌跡是否可追溯、不可由一般使用者竄改，並避免記錄密碼、Token、完整卡號或敏感個資。
- 金鑰是否由適當的 KMS／HSM 或秘密管理機制保護；程式庫不得自行設計密碼演算法。
- 批次、檔案交換、API、委外與雲端整合是否驗證來源、完整性、權限、逾時與失敗重試。
- 正式／測試資料與環境是否隔離；測試工具、debug endpoint、預設帳密及 bypass flag 不得進入正式路徑。

## 業別路由提醒

- 金控：跨子公司資料、集團共用服務、權限邊界及事件傳遞。
- 銀行：帳務與支付交易、網銀／行銀、核心系統介接、ATM 與開放 API。
- 證券／期貨：委託、成交、撤單、行情與風控時序。
- 投信投顧：基金交易、淨值、投資限制、客戶適合度與資料隔離。
- 票券：交易、交割、額度及授信相關狀態控制。
- 保險：要保／核保／理賠、保戶個資與通路介接。

不得將某一業別的控制或規範直接套用到全部金融機構。
