# 結構模型

當問題看起來像工具選型或技術選型時，先用下面的結構模型重新分類。

## 不穩定輸入

- 常見訊號：
  - 上游格式常變
  - 資料品質不一致
  - 來源太多、規格不統一
- 典型解法輪廓：
  - 先標準化輸入
  - 增加前置驗證與分流
  - 把高風險輸入改成人工確認或規則化處理

## 同步問題

- 常見訊號：
  - 多個系統狀態常打架
  - 前後台、資料表、第三方服務不同步
  - 使用者看到的狀態常延遲或矛盾
- 典型解法輪廓：
  - 降低即時耦合
  - 改成事件驅動或批次對帳
  - 明確定義主系統與權威來源

## 對齊問題

- 常見訊號：
  - 使用者想要的和系統做的不同
  - 指令、資料欄位、畫面流程彼此誤解
  - 明明功能存在，但結果總是不符合期待
- 典型解法輪廓：
  - 強化輸入約束
  - 提前暴露選項與預期結果
  - 用介面引導或規則表替代隱性判斷

## 容錯不足

- 常見訊號：
  - 一個小錯就整段失敗
  - 沒有 fallback、retry、人工接手點
  - 使用者無法知道哪一步出了問題
- 典型解法輪廓：
  - 增加降級模式
  - 切出人工補位節點
  - 將長流程拆成可重試的短節點

## 跨格式問題

- 常見訊號：
  - PDF、圖片、表單、Email、Excel 彼此轉換
  - 每多一層格式轉換，錯誤率就上升
- 典型解法輪廓：
  - 減少轉換次數
  - 找原始結構化資料源
  - 在轉換邊界增加驗證與映射表

## 決策延遲

- 常見訊號：
  - 每一步都要等前一步判定
  - 人工審核塞住整條流程
  - 真正重要的決策點被放得太後面
- 典型解法輪廓：
  - 把高價值判斷提前
  - 先粗分流再細處理
  - 將人工判斷集中在最有價值的節點

## 高耦合流程

- 常見訊號：
  - 一段改動會連動多段
  - 每次修正都要跨團隊協調
  - 無法局部替換
- 典型解法輪廓：
  - 重畫責任邊界
  - 用中介格式或契約分離模組
  - 先從流程重排而非技術重寫下手


## 成本可參與化

- 常見訊號：
  - 某段工作對內部是高人工、高時間、高協調、高物流或高維護成本
  - 任務本身具有學習性、體驗性、社交性、地方性、稀缺性、公益性或展示價值
  - 工作時間集中，適合做成預約、梯次、活動、會員任務或社群共作
  - 成果可以被參與者現場使用、帶走、展示、分享、兌換或轉成學習成果
- 典型解法輪廓：
  - 自助流程
  - 顧客參與
  - 體驗化 / 教育化
  - 社群共作
  - workshare / 實物交換
  - 會員任務 / 預約制
  - 企業志工 / ESG 合作
  - 學校課程 / 專題合作
  - 平台媒合
- 風險檢查：
  - 參與者得到的價值是否明確且對等
  - 是否形成變相雇傭、剝削觀感或違反勞動規範
  - 是否需要保險、安全告知、活動許可、訓練或同意書
  - 品質如何驗收，哪些任務不能交給非專業者

## 規則其實比模型更適合

- 常見訊號：
  - 輸入範圍窄、規則明確
  - 錯誤成本高，需要可追溯
  - 團隊需要穩定可控，而不是彈性生成
- 典型解法輪廓：
  - 規則表
  - 決策樹
  - 白名單 / 黑名單
  - 模型僅做輔助排序，不做最終判定
